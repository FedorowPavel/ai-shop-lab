# Архитектура

Учебный монорепозиторий. Цель — отработать AI-flow, не магазин как бизнес.

Оркестратор формулирует задачу и проверяет результат. Агент пишет код после «подтверждаю». Правила — `.cursor/rules/workflow.mdc`.

## Стек

| Часть | Выбор |
|---|---|
| Frontend | Next.js, App Router. UI простой |
| Backend | NestJS |
| База | PostgreSQL 16 + pgvector, Docker |
| Картинки | Pexels API, ключ в `PEXELS_API_KEY` |

Ключ Pexels хранится на сервере. В браузерный бандл его не кладём.

Каталог, когда дойдём до товаров: обувь, джинсы, шорты, майки, рубашки, пуховки, ветровки.

## Границы

- `frontend/` — страницы и вызовы API. Сейчас: `/login` и главная-заглушка.
- `backend/` — HTTP API и миграции. Сейчас: `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`.
- Сессия — подписанная httpOnly cookie `session` с `id` пользователя. Это не JWT. Браузер ходит только на свой адрес (`/api/...`). Next.js пересылает запрос на backend `http://localhost:3001`, поэтому вход не зависит от того, открыта страница как `localhost` или как другой локальный IP.
- `docs/` — архитектура, схема, ADR, заметки к RAG.
- RAG и pgvector в запросах — этап 2. Образ Postgres уже с pgvector, чтобы не менять стенд позже.

## Пробел, который тренируем

Миграции, индексы, транзакции, кэширование, параллелизм. Любое такое изменение объясняется в ответе и в `docs/db-schema.md`.
