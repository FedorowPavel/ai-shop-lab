# 0001. Стек и AI-flow

## Контекст

Лаборатория для перехода с frontend на AI-инженера. Нужен один предсказуемый цикл: задача → подтверждение → ветка → код → тесты → PR. Пробел автора — базы данных, не вёрстка.

## Решение

- Монорепо: `frontend/` (Next.js App Router), `backend/` (NestJS), PostgreSQL + pgvector в Docker.
- Основная ветка `master`. Задача живёт в `feature/task-XXX` и попадает в `master` только через PR (`gh`).
- Код приложения начинается после слова «подтверждаю».
- UI простой. Картинки — Pexels API.
- RAG отложен на этап 2; заметки копятся в `docs/rag-notes.md`.

## Последствия

- Первый коммит каркаса должен быть на `master`, иначе feature-ветку не от чего отвести.
- Любая миграция без абзаца «почему» в `docs/db-schema.md` не считается готовой.
