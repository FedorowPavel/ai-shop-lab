# Deploy check

Стенд лаборатории — локальный Docker. Облако и продакшен не трогать, пока пользователь явно не назовёт среду.

## Шаги

1. Прочитать `docker-compose.yml` и `.env.example`. Не печатать значения секретов из `.env`.
2. `docker compose config` — файл валиден.
3. `docker compose up -d` и дождаться healthy/ready у Postgres. Проверка: `pg_isready` внутри контейнера.
4. Если в образе есть pgvector — одним запросом убедиться, что расширение доступно (`SELECT extname FROM pg_extension` после миграций; до миграций достаточно `SELECT * FROM pg_available_extensions WHERE name = 'vector'`).
5. Миграции: применить штатной командой backend, если она уже есть. Нет команды — остановиться и написать, что проверять нечем. После применения схема совпадает с `docs/db-schema.md`.
6. Тесты и typecheck затронутых пакетов (`npm test`, `npm run typecheck`).
7. Короткий отчёт: что поднялось, порты, прошли ли миграции и тесты, что не проверено.

Падает здоровье контейнера или миграция — не объявлять стенд готовым. Показать ошибку и ближайшую причину.
