# Update docs

Выполнять перед каждым `git push`. В коммит с кодом попадают и правки docs, если код изменил поведение, схему или решение.

## Что обновлять

| Изменение | Файл |
|---|---|
| Новый модуль, граница frontend/backend, внешний API | `docs/architecture.md` |
| Таблица, колонка, миграция, индекс, транзакция, кэш | `docs/db-schema.md` — что изменилось и почему |
| Выбор, который иначе через месяц будет непонятен | новый файл `docs/adr/NNNN-short-title.md` |
| Заметка про эмбеддинги или поиск (этап 2) | `docs/rag-notes.md` |

Нечего обновлять — в ответе одна строка: документация не менялась, потому что поведение и схема те же. Не создавать пустые ADR.

## Схема БД

Для каждого изменения записать:

- миграция: какую инвариант или колонку добавляет;
- индекс: какой запрос он ускоряет (фильтр, join, order by);
- чем оплачен: место на диске, замедление записи.

Файлы миграций не дублировать целиком. В docs — смысл и причина.

## ADR

Коротко: контекст, решение, последствия. Номер — следующий свободный `NNNN`. Не переписывать принятые ADR; новое решение — новый файл.
